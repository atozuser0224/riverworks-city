## 구현되어 검증된 게임 기능

### 도시 건설과 진행

- 21×21 도시 지도, 평지·숲·바위·물 지형, 강과 도로 교량이 있다.
- 지도는 7×7 지역 9개로 나뉜다. 중앙 지역에서 시작해 인접 지역을 코인으로 차례로 구매한다.
- 시청과 이어진 4방향 도로망이 건물의 연결, 생산, 주민 이동, 전력 인입과 반출의 기준이다.
- 건설 가능 지형, 소유권, 기존 도시 건물과 공장 설비의 점유를 함께 검사하며 실패할 때 자원을 쓰지 않고 한국어 사유를 표시한다.
- 건물 건설·철거·증축, 도로·벨트 연속 드래그 배치, 선택·회전·철거 도구를 지원한다.
- `석조술` 뒤 2단계, `도시 계획` 뒤 3단계 증축이 열린다. 주택은 레벨당 주민 6명을 수용한다.
- 5단계 목표가 도시 확장을 이끈다: 연결 건물 12개 → 인구 16명과 빵 4개 → 인접 지역 구매 → 인구 30명과 금속·도구 산업 → `도시 계획`, 인구 45명, 지역 4개. 최종 목표 뒤에도 자유 건설을 계속할 수 있다.

### 자원·경제 9종

`코인`, `목재`, `석재`, `곡물`, `밀가루`, `빵`, `광석`, `강철`, `도구`를 사용한다.

- 원료 생산부터 곡물→밀가루→빵, 광석→강철→도구까지 도시 생산 사슬이 이어진다.
- 주택은 빵을 우선 소비한다. 빵이 없으면 곡물 2개로 한 끼를 대신하며, 식량 부족은 성장·행복·인구에 영향을 준다.
- 인구 24명부터 도구를 선택적 생활 편의로 소비한다. 도구 부족만으로 주택 성장이 멈추지는 않는다.
- 세금과 유지비, 생산량·도구 생산량·수요·반출 통계, 행복과 인구를 계산한다.
- 시장은 빵이 부족할 때 코인으로 기초 식량을 자동 수입한다. 교역 창에서는 자원을 10개 단위로 직접 구매·판매한다.
- 투입기를 붙이지 않은 생산 시설은 기존의 도시 공유 재고 방식으로 계속 작동한다. 자동화는 원하는 구간부터 점진적으로 추가할 수 있다.

### 같은 도시의 공장과 물리 물류

- 공장은 별도 화면이 아니다. 도시 한 필지를 2×2로 나눈 42×42 미세 격자에서 주택·도로·주민과 같은 카메라를 사용한다.
- 설비는 구매한 영토와 실제 도시 지형을 따른다. 채굴기는 자연 바위 위에 두며, 기계와 건물이 서로 겹치지 않는다.
- 운송 벨트·투입기·전신주·분배기는 도시 도로와 공존할 수 있다. 물 위에서는 도로 교량이 먼저 있어야 한다.
- 물자는 실제 개체로 이동한다. 설비 입력·출력·이동 중 화물은 공유 재고에 미리 더해지지 않는다.
- 도시 시설의 입력·출력 버퍼는 각각 총 80개, 생산 설비의 입력·출력은 각각 24개다. 출구가 막혀 버퍼가 차면 원료를 더 소비하지 않고 생산이 대기한다.
- 투입기는 모든 물자 또는 특정 자원 필터를 쓴다. 분배기는 앞과 왼쪽 출구를 번갈아 사용한다.
- 전력 인입구는 도로로 시청에 연결되고 도시의 남는 전력이 있어야 작동한다. 전신주는 6칸까지 전력망을 잇고, 동력 부족 시 일부 기계가 멈춘다.
- 연결된 시청·도시 창고는 모든 물자를 받고 내보낸다. 시장은 빵·도구만 받고, 반출 부두는 도로에 연결되어야 공유 재고와 반출 통계에 반영한다.
- 설비 철거 시 내부와 이동 중 물자는 공유 재고로 회수되고 건설비의 35%를 환급한다.

### 주민과 도시 생활

- 모든 주민은 결정적으로 생성되는 이름, 집, 일자리, 시장·공원 여가 목적지를 가진다.
- 주민은 집→직장→시장/공원→집 순환을 따르며 시청과 실제 4방향 도로·다리로 경로를 찾는다. 선택하면 이름과 현재 목적지를 볼 수 있다.
- 화면에는 최대 128명이 보행하며 나머지는 실내 상태로 계속 시뮬레이션된다.
- 산업 시대 도시 트럭은 도로 연결을 보여 주는 시각 연출이다. 물자를 싣거나 경제를 바꾸지 않는다.
- 검증된 기본 주민 행동은 로컬 규칙 기반이다. 주민은 개별 생산·소비 주체가 아니며 도시 경제는 별도 시뮬레이션이 한 번만 계산한다.

### UI, 조작, 피드백과 접근성

- 상단에는 작은 자원·시대·연구·인구 표시, 하단에는 건설 분류·도시 기능·시간 제어가 있다.
- 건설 목록은 필요할 때만 펼치고, 건물·설비·주민 정보는 선택했을 때만 오른쪽에 연다. 목표·현황·영토·교역·연구·메뉴도 모달로 연다.
- PC는 마우스, WASD, 휠, Q/E 회전, F 시청 보기, G 설비, R 회전, H 주택, T 연구, Delete 철거, 1/2/3 속도, Space 정지, F5 저장, M 음소거, F1 도움말을 지원한다.
- Android는 탭·길게 누르기·한 손가락 이동·두 손가락 이동/핀치, 화면 회전·철거·취소·속도 버튼, 시스템 뒤로 가기의 단계적 닫기를 지원한다.
- v0.5 작은 HUD는 Windows 1600×900과 1280×720에서 기본 17.5%, 선택 정보 포함 25%의 월드 입력 차단 면적으로 검사됐다. 버튼은 한국어 이름과 의미 아이콘을 함께 쓴다.
- v0.6 피드백은 건설·철거·증축·영토 확장·선택·실패·교역·저장·연구 시작/완료·시대 전환·목표 완료와 공장 건설/철거/제조법/이송에 반응한다.
- 세계 파티클·대상 움직임·주요 사건 카메라 반응, 버튼 hover/press/release, 실패 흔들림, 패널 등장, 자원 수치 pulse를 MMF_Player로 재생한다. 빠른 연속 건설은 제한하고 효과를 풀링한다.
- `움직임 줄이기`는 저장되는 실제 네이티브 MMF 프로필이다. 카메라 흔들림을 끄고 이동·크기를 줄이면서 상태 피드백은 유지한다.

## v0.6.2 UI 다듬기 — Windows 검증 완료

- 연구 창은 화면 크기에 맞춰 폭과 높이를 제한하고, 좁은 화면에서는 시대 열을 가로 스크롤할 수 있다. 메뉴·현황·영토·교역·설비 구성 등 모달도 같은 카드·딤·44×44 닫기 형식과 화면 경계 제한을 공유한다.
- 단우 대화는 실제 렌더 높이를 재어 맞는 분량으로 페이지를 나눈다. 건설 목록이나 활성 도구 막대와 동시에 열리면 그 위로 이동하며, 자주 쓰는 `접기·단우 보기·계속` 외 기능은 더보기 메뉴에 둔다.
- 설비 구성은 용광로와 조립기에 맞는 제조법만 연속 배치하고, 투입기 필터와 도시 재고 투입은 격자에 놓는다. 활성 섹션에 맞춰 창 높이를 바꿔 빈 슬롯과 불필요한 여백을 줄였다.
- 주민 AI 상태는 모드와 설명이 같은 의미일 때 한 번만 표시한다. 오래된 도움말의 교역 조작도 현재의 구매·판매 버튼 방식으로 고쳤다.
- `HudStyle`이 Surface·Raised·Text·Muted·Accent·Positive·Danger 색과 11px 본문·22px 제목·44px 터치 크기를 함께 관리한다. Galmuri11에는 가짜 굵기를 쓰지 않고 Canvas는 화면과 DPI에 맞춘 정수 배율을 적용한다.
- 하단의 `주거·생산·산업·도시·설비·물류` 여섯 탭은 그대로 유지한다. 건설 목록은 내용 폭에 맞춰 스크롤되며, 호버 또는 길게 누르기로 전체 설명·비용·잠금 사유를 열고 선택한 도구 막대에도 비용을 표시한다.
- 상단의 광석·강철·도구는 해금되거나 보유한 뒤 표시되고, 교역 창은 보유 코인·물자와 구매·판매 가능 조건을 보여 준다. 영토 창은 인접 필요와 코인 부족을 구분한다.
- 건물·설비 인스펙터는 상태, 생산·제조법, 레벨, 투입·출력 재고와 좌표를 분리한다. 전력 행은 전력을 실제로 쓰거나 공급하는 대상에만 표시하고 연결 끊김·원료 부족·전력 필요 상태는 위험 색으로 알린다.
- 사용되지 않던 별도 `FactoryHud` 파일은 제거하고 통합 도시 HUD만 남겼다.
- 위 항목은 Windows 실행 파일에서 네 가지 렌더 크기로 검증했다. 물리 디스플레이·Android 실기기 검사와는 구분하며 상세 결과는 [검증 기록](VERIFICATION.md)에 있다.

## v0.6 추가 구현과 검증 상태

### 마을 서기 단우 튜토리얼 — 구현·PC 검증 완료

- 11단계: 인사, 시청 선택, 연결 도로, 주택, 벌목장, 서재, 윤작 시작·완료, 기계 동력 조언, 저장, 마무리.

- 단우는 별도 초상화 대신 기존 시민과 같은 3D 모델을 사용하고 청록색 옷으로 구분된다. 실제 도로를 따라 안내 위치로 걸으며 카메라가 추적하고, 수동 카메라 조작 후에는 `단우 보기`로 추적을 다시 시작한다.
- 대사는 Galmuri11 도트 한글 폰트로 한 글자씩 표시되며 진행·완료 소리, 현재 페이지 즉시 표시와 마지막 페이지 확인을 지원한다.
- 기본 안내 뒤에는 증축·생산·연구·전력·물류·영토·주민 AI·저장과 화면 효과를 다루는 19개 후속 기능 안내가 상태에 맞춰 하나씩 열린다. 기능 목록에서 직접 골라 읽거나 도시·생산·연구·공장·영토의 다섯 주제로 조언을 요청할 수도 있다.
- 순수 진행·저장 검사와 Windows Unity 런타임에서 실제 HUD 입력, 시청 도착 연출, 단우 보행·카메라 추적, 11단계 진행과 19개 안내 표시를 확인했다.

### 선택형 OpenRouter 주민 행동 — 구현·계약 검증 완료

- 사용자 선택에 따라 로컬 규칙을 기본값으로 유지하면서 클라우드가 주민의 짧은 방문 계획을 제안하는 구조다.
- Unity 설정 화면과 클라이언트가 게이트웨이 상태 확인, 기능 켜기·끄기, 계획 요청·적용, 도시 교체·재불러오기 때의 요청 무효화를 처리한다. 게임과 APK에는 OpenRouter 제공자 키를 넣지 않는다.
- 게이트웨이는 한 번에 최대 16명, 분당 최대 2회, 시간당 최대 $0.50, 일일 최대 $2.00 한도를 적용한다.
- 모델은 홈·직장·시장·공원·시청 광장 중 현재 도시에서 소유하고 도로로 도달 가능한 허용 대상만 선택한다. 생산량·가격·재고·세금 등 경제 수치는 모델이 바꾸지 못한다.
- 응답은 ID, 도시 세대, 허용 의도/대상, 실제 경로, 만료 시간과 형식을 다시 검사한다. 오류·한도 초과·설정 누락 때는 주민이 규칙 기반 행동을 계속한다.
- 주민의 짧은 기억은 실행 세션에만 있고 저장 파일에는 남지 않는다. 클라이언트 프로세스는 제공자 비밀키를 받지 않는 게이트웨이 구조다.
- Node.js 게이트웨이 검사와 Unity `MOCK_CONTRACT` HTTP 런타임에서 상태 확인, 계획 적용·보행·도착, 잘못된 JSON·허용 밖 목적지·중복 ID·오래된 세대 거부, 저장 비영속성과 규칙 기반 복귀를 확인했다.
- 현재 OpenRouter API 키가 설정되지 않아 실제 제공자 호출은 검증하지 않았다. 계약 모의 검증 결과를 실제 LLM 성공으로 간주하지 않는다.

## 현재 포함되지 않은 범위

플레이어 청사진, 다중 선택/undo, 건설 노동자, 개별 주민 경제, 도시 서비스, 실제 화물 차량·철도·선박, 재고 우선순위, 계절·재해, 여러 저장 슬롯, 장식/업적, 멀티플레이와 모딩은 아직 구현 기능이 아니다. 선택형 클라우드 주민 행동은 방문 계획만 제안하며 생산·건설·교역을 대신 제어하지 않는다.
